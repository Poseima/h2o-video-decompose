# 运行与验收

## 依赖和入口

基础拆解、选装音频及 3DGS 的依赖和自检见[安装与验证](../INSTALL.md)。示例从 Skill 根目录执行。也可在项目目录中使用脚本的完整路径。为每次分析选择新的输出目录。

~~~bash
python scripts/decompose.py scan "/path/to/source.mp4" "/path/to/scan" \
  --interval 1 --start 0 --end 1200 --max-candidates 60

python scripts/decompose.py measure "/path/to/source.mp4" "/path/to/result" \
  --scan "/path/to/scan/source.json" --plan "/path/to/plan.json" \
  --max-side 1920 --review-step 12 --annotated-frames

# 针对任意镜头做 2D/3D 场景范式自动判别、全场景 3D 物件 BOM 盘点与通用 3D / Blender 逆向精测：
python scripts/decompose.py scene3d "/path/to/source.mp4" "/path/to/out_3d" \
  --frame 738 --window 8
# 已标注物件时可追加 --objects-plan "/path/to/objects_plan.json"。
# 有平面四角或尺度依据时可追加 --corners、--rect-size、--focal-mm 或 --depth-m。
~~~

scan 的 --start/--end 接受源帧号，--end 省略表示扫描到结尾。--interval 是故事板的取样秒数。source.json 和 frames.csv 保存整个流的索引。candidate-cuts.json 记录所选范围内灰度差最大的帧。`lookdev-keyframes.json` 按光学工况（局部自发光/高光峰值、明暗反差峰值、暗调近景及窗口基线）自动推荐三维分析与验收应覆盖的代表帧，避免人工稀疏抽帧漏掉最难的光影瞬间。长视频或密集快切区可分窗，保留至少一帧重叠。若时间轴异常，保留源 PTS 并以帧号对齐。

工具使用首个视频流和编码方向。手机素材如有旋转元数据，按编码方向选区，或先创建转正的分析副本再重新索引。像素坐标以分析尺寸为准，默认长边上限 1920。JSON 记录编码尺寸和分析尺寸。高分辨率或长镜头触发内存上限时，缩短测量窗口或降低分析分辨率，并注明这一选择。

## 计划示例

以下帧号和选区是示例，按原片画面修改。

~~~json
{
  "shots": [
    {
      "id": "screen",
      "name": "屏幕拉远",
      "start": 120,
      "end_exclusive": 180,
      "ref": 145,
      "boundary": "reviewed hard cut",
      "bridges": [130, 163],
      "stable": [[0.08, 0.12, 0.92, 0.70]],
      "exclude": [[0.72, 0.24, 0.90, 0.40], [0.05, 0.82, 0.95, 0.98]],
      "anchors": [[0.5, 0.45], [0.34, 0.45], [0.66, 0.45], [0.5, 0.34], [0.5, 0.56]],
      "zones": {
        "title": [[0.11, 0.16, 0.85, 0.32]],
        "body": [{"keys": [[120, 0.14, 0.36, 0.91, 0.60], [179, 0.21, 0.39, 0.84, 0.57]]}]
      },
      "independent_points": [
        {"name": "panel_corner", "reference": [0.82, 0.33], "observations": {"155": [0.78, 0.34]}}
      ]
    },
    {
      "id": "transition",
      "start": 180,
      "end_exclusive": 188,
      "ref": 185,
      "geometry": "none",
      "zones": {"center": [[0.2, 0.2, 0.8, 0.8]]}
    }
  ]
}
~~~

- 框为 [左, 上, 右, 下]，点为 [x, y]。坐标归一化为 0–1，x 向右、y 向下。stable、exclude 和 zones 支持关键帧框。框只筛选特征，运动由原片匹配拟合。排除打字、字幕、局部动效、光标和独立检查点周围。
- anchors 依次为中心、横向左端和右端、纵向上端和下端。每个 H 将本段参考帧的像素列向量映到当前帧，前两项各除以第三项。参考帧输出恒等矩阵。倾角描述参考线在画面中的角度。
- 同屏多平面可用另一份计划单独测量同一时间段。活动项可以另外做模板相关或记录观测点。将当前帧的活动点用 H 的逆变换送到静态参考帧。保留原坐标、换算坐标、匹配强度或手动检查依据。
- geometry 为 none 适用于只测可见锐度或没有足够共同结构的段。limited 表示有限估计，unresolved 留空，single_frame 表示没有跨帧运动可测。

## 输出与复核

measurements.csv 和 JSON 逐帧记录投影及锐度。shots.csv 包含各段范围和参考帧。JSON 的 independent_checks 保存观察值、预测值和误差。接力留出误差不含早期桥接累积。地图、表格、游戏 HUD 等重复纹理应看覆盖图，局部拟合误差低也可能配到另一块纹理。边缘宽度比较一般要求每区至少五个样本。图的 Zone 编号见 zone-legend.txt。蓝格为验证通过或参考，橙格为有限估计，橙圈是锐度取样，绿点是独立观察。

--annotated-frames 保存以源帧号编号的 PNG。连续区间且原片为恒定帧率时，可以按实际帧率合成，例如 630 帧起的 36 帧。

~~~bash
ffmpeg -framerate 30 -start_number 630 -i "annotated/%09d.png" \
  -frames:v 36 -an -c:v libx264 -crf 17 -pix_fmt yuv420p "review.mp4"
~~~

可变帧率按原片 PTS 差写入每帧的时长，并对比回读时序。存在未测区间时分段合成或保留对应时间间隔。

镜头表字段可用「源帧与起止时间｜边界类型｜画面与内容｜几何和运镜｜清晰度变化｜独立动画｜误差和缺测」。内容与声音按源时间对齐，记录转写或声音事件识别中的缺口。

## 连续动效短窗精测

按[连续动效的触发条件](../SKILL.md#连续动效)选窗。每个窗口尽量保留动作前的稳定帧与动作结束后的稳定帧。动作跨窗时保留重叠并验证共同锚点。原速确认节奏，慢放或逐帧锁定阶段。已有复刻时可用同一源间隔做局部帧差对照，帧差峰值须回查原片和复刻的连续画面。

先识别活动项附着于画幅、静态页面还是独立平面。以页框、固定文字或地线等非活动结构估算该局部的整体运动，避开参与动效的区域，用另一个固定锚点检查逆投影。输出坐标与测量尺寸的换算见[坐标与回退](#坐标与回退)。

| 动效示例 | 按层记录 | 复刻对照 |
| --- | --- | --- |
| 橙线画完后灰线抬升 | 在同一图表坐标量橙线端点，另量灰线峰顶与两侧轮廓。在笔触交叠处取仍可辨的轮廓点，记录显露或淡化区间。 | 核对橙线画完、灰线开始变形、轮廓趋稳的先后，检查峰顶与肩部是否随时间一起变化。 |
| 任务标飞向接收卡 | 分别量任务标中心、尾迹端点、接收卡边缘、外齿轮角度和内指针角度，记录状态文字首次可辨时刻。重复齿形的转角用邻帧连续性复核。 | 核对蓄力、飞出、尾迹出现、卡片轻弹和两部件反向旋转的相对时差。 |
| 小车撞到挡块 | 用车身下部色带上缘量车身角度，在车身坐标量车尾角度。分别记录接触、车身正反两次倾斜、车尾跟随与停稳。轮缘和地线可作为独立核对。 | 核对接触时车身与车尾的回摆顺序，以及轮子是否在接触阶段保持贴地。 |

- 分层事件表可用「对象或图层｜事件｜源帧或帧区间｜源 PTS 或 PTS 区间｜与前一事件的时差｜证据与置信度」。逐帧表补充参考帧、坐标域、取样区、量值和单位。需要交给渲染时在复刻清单登记读取的字段或手工关键帧。
- 用同一局部动作前的波动、独立轮廓点和邻帧判断弱变化是否可辨。压缩、拖影、遮挡或参考误差会影响时点和幅度。只有事件顺序可靠时可只给顺序或区间，量值留空。标明实测区间及复刻使用的近似、插值或手工关键帧。
- 验收短窗与原片按源帧或 PTS 对齐，并包含起动前和末段。先原速看节奏，再慢放核对错峰、停顿、接触、回弹和衔接。抽查关键帧、局部叠图及轨迹，对比可见事件的时差与主要量值。局部帧差或全画幅相似度用于辅助定位，验收依据还包括这些动作事件与轨迹。

## 能力边界预检与预期对齐

纯拆解先用一两句说明目标范围、方法及交付，需求明确即可分析。复刻先扫查完整目标范围，挑出决定还原上限的镜头，比较可行路线。查官方文档、模型说明和与镜头条件相近的实际案例，记录来源和适用条件；同时检查用户已有工程与资产、软件与插件版本、本机或指定远程渲染机的算力、外部模型或服务访问权限。关键依赖以实际可读、可调用或最小验证为依据，未能验证则注明。

给用户的计划先写推荐路线和原因，再按需列出「镜头时间段｜可编辑还原的内容｜1:1 路线与核验依据｜仍需的具体资源」。外部建模、实拍或视频生成方案写明输入、权限、费用和编辑粒度；费用未知时给出待查项。把路线与其他可同时回答的问题放入[开工选择问卷](#开工选择问卷)。

1. **视觉审查 + 客观信号交叉定级**：
   - **视觉审查（决定性依据）**：通览 `scan` 生成的故事板与代表帧，按[能力边界矩阵与注册表](capabilities.md)逐镜识别画面是否包含实拍真人表演、手绘逐帧作画、影视级写实角色/毛发布料、重度物理 VFX（流体/爆炸/碎裂）、剧烈手持自然外景等 `🔴 L3` 元素，或复杂有机道具/近似字体等 `🟡 L2` 元素。
   - **客观信号辅助**：对候选三维或复杂镜头可抽查 1–2 个代表帧跑 `decompose.py scene3d`，读取顶层 `reconstructability_signals`（`geometric_structure_confidence`、`temporal_stability_hint`、`suggested_engine`、`automated_warnings`）。当 `geometric_structure_confidence == "low"` 或触发非刚体/低内点警告时，重点复核是否属于无法稳定求解几何的 `🔴 L3` 镜头。
2. **按资产选工具，执行时验证。** 先查工程、资产库与清晰邻帧，再发现当前会话实际开放的工具、相关技能和制作环境。位图优先核查内置 Image Gen 或其他可用生图工具；选择代表资产时，优先覆盖会影响多个镜头或在画面中最清晰的部分。将原帧观测到的构图、色调、光照和可见轮廓写入制作要求，生成独立的可替换素材。窗口、文字、遮挡、拖影及三维运动按各自的原生路线重建。

   计划模式只写试做对象、工具和验收条件，结论记为待验证。执行阶段主动调用已获授权且可用的路线，将样本放入工程，以实际尺寸、遮挡、出现时长导出，对齐源帧并原速回看。记录可见差异，按约定轮数调整和复测。总负责人将达标版本发布到共享库并登记引用段；资产试做通过后仍须完成分段与整片验收。
3. **确需用户介入时只问一件具体的事。** 若负责人缺工具，总负责人先核查自己与其他制作角色，安排可用角色试做。仅当试做或技术核验表明仍缺必要信息或权限时，简述哪个镜头、已试过什么、尚缺什么以及它影响哪处可见细节。例如：「窗内插画右缘在回摇时露出。试绘合成后，右缘人物的手势仍对不上，现有邻帧也看不清。你有这部分的清晰参考吗？」等待期间推进不依赖该资源的工作。
4. **局部例外须单独授权。** 用户明确答复所需资源无法提供、且核实的重建路线仍不能达标后，才可说明该资产的替代方法、影响时段和可见差异。用户明确接受该做法后，将「资产标识及实例｜源帧与 PTS 区间｜资源缺口及确认｜获准做法、差异及用户决定」写入清单，随任务交给建模、分段及验收负责人。未回复、暂时找不到或仅确认缺失，均维持 1:1 目标；同一资产在其他时段复用时核对授权范围。

| 走查场景 | 正确处理 |
| --- | --- |
| 工程中已有火箭桌布纹样 | 核对版本、图案方向及可见范围后复用，按原帧对照。 |
| 缺火箭桌布，片头和后段再次出现同一桌面 | 首次计划列出 Image Gen 等可用生图路线。执行时生成一份云海桌布，单做尾焰动画，两处引用同一达标版本。 |
| 窗内插画只露出一部分 | 生成插画层，放回窗口核对实际可见轮廓和颜色。可见部分达标即推进；若仍有可见差异，按约定返修。 |
| 多窗口快速散开并产生密集拖影 | 复用同一批插画，逐窗按源帧重建轨迹、叠放和拖影衰减，导出后连续对照。 |
| 子代理无生图工具，或试绘后插画右缘仍缺依据 | 总负责人先自行调用或转派具备能力的角色。复核试做记录和清晰邻帧后仍缺依据时，只问右缘的清晰参考。 |
| 用户确认插画资源缺失，重建仍缺依据，随后明确接受只替代指定时段的右缘图案 | 仅在批准区间实施并单列差异；桌布、拖影及其他时段继续按 1:1 验收。 |

## 资产盘点与独立建模

1. 总负责人给盘点子代理分配覆盖全范围的镜头或连续时段。逐帧索引与相邻参考供追查瞬间露出、遮挡、远景、反射、立体文字及前后景小物件。用 `scene3d` 的物件裁图和 BOM 辅助查找，回放每段并补登遗漏。每个可辨资产都记录实例、各次可见的左闭右开源帧区间与 PTS。难辨项保留截图和待确认说明。
2. 总负责人汇总全部回报，核对覆盖，按身份合并同一物件在不同机位、遮挡前后的记录，区分同类模型的多个实例。每项给固定标识；不连续出场保留多段。面向用户的报告每行展示代表截图（多角度有助辨认时并列）、名称、全部出现时段和拟用来源。底表链接回原帧、实例和分段。示例：同一乘客在 1.2–2.0 秒、6.4–7.1 秒两次可见，报告只列一行、列出两段时间，来源写「采用用户模型」。请用户核对漏项、误合并和替换项，收到确认后安排建模。
3. 单独调度建模子代理，为每件资产指定唯一负责人。将用户替换资产导入并核验，将其余经确认的资产建成可编辑模型，随件提交材质、所需绑定、依赖及原帧对照。总负责人逐件核对清单覆盖、尺度、轴向、原点、材质和依赖，从工程入口重开并验证实例引用。待完整共享库核验并发布版本后，才启动另一批分段子代理分析和复刻；未通过的资产退回原建模负责人。
4. 非 Blender 的二维项目在路线确认后直接分段。混合项目先完成三维资产阶段，再由分段负责人制作，二维层共用字体、组件、坐标与合成设置。

## 开工选择问卷

复刻任务固定采用**主从 Agent 协作模式**（不提供单 Agent 制作选项；纯拆解/分析任务可由总负责人直接执行）。总负责人先预览原片、核实工具和资源。普通对话与计划模式优先使用各自可用的 Ask User Questions 控件，在一次调用的 questions 列表中提交多道独立选择题。每题给出可行选项，推荐项排第一并按控件格式标记，附一句针对本片的取舍。用户也可自填答案。无控件时在同一条消息中列出相同的编号题，支持一次回复「1A、2B、3A」。

按控件容量合并当前适用、可独立回答的未决题。容量为三题时，优先把「技术路线」「复刻档位」「子代理模型」放在首批。若用户已指定 Blender 等路线，略去该题，用「推理强度」「最大并发数」「自有替换资产」或「每段返修轮数」补位。容量更大时直接合并更多适用题。

| 独立问题 | 给用户的选项与依据 |
| --- | --- |
| 技术路线 | 写明各可行路线能编辑什么、本片最难还原什么。仅一条可行时说明依据，让用户选择采用或调整需求。 |
| 复刻档位 | 首项始终为精细复刻（默认推荐），每段最多 2 秒。均衡、快速分别最多 5、10 秒。三档均以 1:1 为目标并采用相同验收标准。95.267 秒示例分别至少 48、20、10 段。 |
| 子代理模型、推理强度、最大并发数（各一题，复刻必问） | 复刻一律走主从模式，核实各阶段可用模型、支持的强度与实际名额。若各候选模型支持相同强度选项，三题同批；若选项随模型变化，先问模型，强度留到下一批，只展示所选模型支持的值。并发选项附本片预计批次。 |
| 自有替换资产（适用时） | 说明可自行重建和可指定替换的素材。如用户已明确全量重建或给出替换范围，直接登记。 |
| 每段返修轮数 | 给出至少一轮的选项，说明额外轮次可重点检查哪些镜头。与当前其他独立问题合并展示。 |

仅把用户实际提交或已明确说出的选择记入任务表，注明适用阶段。预选尚未提交时等待。部分作答、旧计划续聊或笼统回复「开始执行」时，集中补问缺项。全部适用项答齐后才展示最终计划与逐段分工，用户确认开工后再首次派发分析或制作任务。

## 开工分工确认表

## 分段派工与任务交接

每位分段子代理在本项目只负责一个正式时间段，从分析、制作、导出到对比、返修和复测均由原负责人完成。时长上限适用于分段制作，盘点与建模按资产范围安排。下表示例按目标范围 95.267 秒、可并发 3 人、每段用足上限估算。

| 档位 | 每人上限 | 至少需要的段数及负责人 | 至少需要的批次 |
| --- | ---: | ---: | ---: |
| 精细复刻 | 2 秒 | 48 | 16 |
| 均衡复刻 | 5 秒 | 20 | 7 |
| 快速复刻 | 10 秒 | 10 | 4 |

实际计划按源显示时间从范围起点排到终点。每段终点最迟为起点加所选上限，可提前收在已核实的切镜或动作边界，最后一段取实际余量。将各段首尾相接，核对逐帧归属。按三档分别统计预计段数，批次用段数除以可并发人数向上取整。提前收段可能增加段数。名额不足时分批启动，下一段派给新的负责人。

1. 设本责任段在源时间轴上的起止为 `T0` 和 `T1`。精测窗依次为 `[T0 + 2i, min(T0 + 2(i+1), T1))`，最后一段按实际余量收尾。若范围截至源片末帧，优先用末帧 PTS 加实际帧时长得出结束时刻。以扫描输出的 `frames[].time_s` 分派源帧，两端分别取 PTS 不早于边界的第一帧，到源片末尾时用帧数作排他上界。窗首落在上一帧的显示时长内时，沿用该帧状态至新帧到来，上一帧只作该窗参考。PTS 缺失或不可靠时，依据帧号和可验证帧率估算。两者都无法验证时按已核对的镜头帧段继续，并标记时间范围待复核，待核实后再确认档位时长和覆盖。
2. 并行时，总负责人用 FFmpeg 按责任段的源帧范围切审阅副本，逐帧核对首尾，测量仍以原片帧索引和 PTS 为准。副本若从零计时，附首帧在源时间轴的位置。整窗没有新帧时提供持续显示的参考帧，仍保留该窗时长。跨窗动作附前后的稳定参考帧或读取原片的范围。重叠部分供测量、对照和衔接，工程合并时每个源帧仅由一个责任段贡献。`scan --interval` 控制故事板取样，精测窗按上述时间轴单独建立。
3. 总负责人统一工程或引擎、画幅、时间基准、图层和坐标。同镜跨窗沿用同一镜头编号、共享图层标识和锚点，登记窗首尾的状态及动作仍在延续的属性。跨窗更换参考帧时按[坐标与回退](#坐标与回退)换算。同一窗口内如有实际切镜，分别保留相应时间和层级。
4. 一张任务表登记「阶段及任务｜档位｜源帧区间、起止显示时间及实际秒数｜镜头、精测窗和参考帧｜前后段｜共享资产标识与版本｜负责人显示名｜已确认模型及推理强度｜约定及已用返修轮数｜依赖、进度及交付路径｜对比证据及验收状态」。盘点、建模、分段制作分别排队；总负责人每次只派依赖已满足的任务，实际并发取阶段已确认上限与可用名额的较小值，完成一项再补位。创建子代理时按宿主支持的方式应用已确认的模型与推理强度；使用继承模式时先核实实际组合一致。排队补位、转派与返修沿用对应角色的已确认配置。若新角色未覆盖、组合不可用或需要变更，先说明受影响任务并向用户确认具体组合，再创建或转派。有名额限制时按队列顺延（即使最大并发降为 1，也须逐批派发独立子代理串行接力，严禁退化为总负责人单 Agent 包办）；若宿主环境完全不支持或长期无法创建独立子代理，直接向用户说明阻塞并暂停复刻，严禁回退到单 Agent 模式。
5. 连续镜头必须跨人时，交接重叠参考帧，以及边界两侧的角色坐姿、动作、物体空间位置、相机位姿和速度、光色、遮挡及声画状态。分段负责人引用同一版资产，按同一源时间轴检查边界两侧的运动，重叠参考只参与核验。对本来就在场的主体，核查运镜时从画框或遮挡边缘连续入画的过程。

默认用简体中文给盘点、建模及分段角色命名，例如「维港建筑建模」「第 03 段｜拖动窗口｜4–6 秒」。新建文档可命名为 `第03段-拖动窗口-对比与返修.md`，标题和进度使用「逐帧对比」「连续性检测」等中文术语。宿主限制内部标识时，在任务表保存内部标识与显示名的对应关系。用户指定英语时，可用 “Segment 03 · Window drag · 4–6 s” 和 `Segment-03-Window-Drag-Review.md`，派工说明和验收摘要同步改用英语。

### 项目目录与共享资产

1. 总负责人开工时确定项目根目录，优先沿用用户指定的位置或现有工程，遵循工作区存放约定。按引擎和现有工程决定目录名、层级和记录格式。在任务清单中标明项目根目录和打开或渲染工程的入口。
2. 在任务清单中统一登记共享素材、字体、模型、模板和公共组件，或链接工程已有的资产清单。每项记录标识、可访问路径及版本。引擎支持时优先用工程相对路径。派工前核对各负责人可以读取依赖，在交接中注明本窗实际要用的资产版本、共用图层及本窗的工作与交付位置。同镜跨窗按同一份清单复用资产。
3. 子代理只写自己的工作包，总负责人维护总工程。分段发现共享资产问题时附源帧和受影响镜头，退回该资产的唯一建模负责人。总负责人验收新版、保留旧版，列出所有使用段，通知统一切换并复测相邻接缝。
4. 总负责人按交付更新任务表。进度交流只写已完成的具体片段或资产、影响交付的问题和接下来的一步。需要用户选择时说明对效果、工期或成本的影响；完整日志留在项目记录。

### 原片效果清单与跨段验收

扫查全片后、分段制作前，按[重点效果清单与逐项验收](effects.md)建立逐镜可复核的通过条件，并把跨段效果标识附到所有相关工作包。每段实际导出按本段可见范围核对，总负责人再对最终整片逐项跑完整效果区间，重跑连续性检测。摘要优先列最影响观感的差异、已修好及仍缺证据的项目。样片或单项通过不能替代整片结果。

### 每段制作与返修

1. 按[逐帧精测](../SKILL.md#逐帧精测)固定参考帧和坐标，登记切镜、构图、关键动作帧、图层轨迹、声画锚点与缺测，再按[复刻时读取哪些数据](#复刻时读取哪些数据)构建可编辑片段。保存原片与复刻的源时间对齐预览，以及可编辑子工程、实测数据和差异记录。
2. 把审阅片段、原片静帧和其他取样画面放在分析或对照材料中。检查复刻工程及渲染素材的来源，禁止把原片片段、静帧、截图、裁切、抠图或任何原片像素作为底图、纹理或其他可见层。可把实测的构图、轨迹、颜色和时间写入独立重建的图层。生成素材单列替换入口和内部编辑限制。
3. 分段负责人遇阻时，交回源帧、已试路线与结果。总负责人按[能力边界预检与预期对齐](#能力边界预检与预期对齐)核查可用能力并调度，分段负责人接回共享素材后继续合成与复测。各段仅执行清单中与本段资产、时段匹配的已批准例外。
4. 每段首版记为第 0 版。原负责人按源 PTS 同步播放原片与实际导出，核对原速、关键帧、接缝及动作前后。三维段对双方对应帧分别运行 `scene3d`，再执行下方的严格对照。二维段分别运行 `scan` 与 `measure`，用各自的帧索引、对应锚点和测量计划对比位置与时序，对同范围视频执行 `lookdiff` 检查外观。混合段分别核对三维底景、二维叠层及最终合成。外观候选由负责人回看原帧判读。
5. 每段默认至少一轮返修，首版不占轮数。原负责人记录「源时间及图层｜原帧与当前版差异｜修改｜同范围重渲染及复测结果」。若所有适用检查均通过且无可修差异，保留对照证据并注明本轮无修改。轮数用尽仍有差异时，带具体时间点和证据交回总负责人，保留待复核或需返修状态。

## 复刻时读取哪些数据

先用核对过的切点确定镜头范围。给每镜写一行复刻清单「源帧范围｜1:1 路线、待补项及获准的局部例外｜参考帧与分析尺寸｜图层及坐标域｜字段或观测文件｜关键事件帧｜缺测与回退｜验收锚点」。同一镜头的多个测量窗共用一个镜头编号，另记各窗的参考帧。清单可以用 Markdown 表格加人工观测记录，现有脚本输出可直接使用。

| 对象 | 数据来源 | 渲染接入 |
| --- | --- | --- |
| 镜头、打字、显隐、字幕和声音 | `shots[].start`、`end_exclusive`，`frames[].frame`、`pts_s`、`time_s`、`duration_s`，另记事件首帧、完成帧或原声起点 | 恒定帧率时按源帧号对齐。可变帧率时以源首帧 PTS 为零点，用 PTS 差和帧时长绑定渲染时间，并核对导出后切点。字幕按画幅位置独立合成 |
| 屏幕、纸页及其固定内容 | `shots[].reference_frame`、`analysis_size`、`frames[].geometry.H` 和 `geometry.status` | 在参考帧标定文字、边框和固定图形。每帧应用同一个投影；页内字距、字号和位置由排版定义 |
| 有独立运动的元素 | 逐帧角点、基线、端点、可见面积或透明度观测。记录帧号、坐标域、置信度和遮挡 | 以静态平面移除相机运动后再拟合局部轨迹。确认独立平面的遮挡或相对位移后，另用参考帧和矩阵。画幅固定的元素直接在画幅坐标定位 |
| 分区清晰度 | `zones.<区域>.q30`、`median`、`n`、`sharp_xy`，以及 `focus.evidence` | 页面投影后用分区模糊或遮罩。先以参考帧匹配可比边缘，复测渲染的边缘宽度，再随帧更新。剔除对象离场后采到的其他内容，样本不足的区域标为缺测 |
| 快推、甩动或翻页的拖影 | 可辨边缘的拖影方向、长度与出现区间。记录用于估计的局部及可信度 | 在画幅空间应用方向模糊，或在快门区间内对可见运动多次采样。只从轨迹或模糊外观推断的参数标为回退 |
| 字形、光色、阴影和纹理 | 字形对照、基线和字距、亮度剖面、色值、边缘取样 | 在参考帧校准静态构图。随页面的效果挂在页面层，固定于画幅的效果在投影后合成 |

### 坐标与回退

- 以列向量表示像素点，左上为原点。若 `A` 把工程图层坐标映射到测量参考帧，`H_f` 把测量参考帧映射到当前分析帧，`S` 把分析像素映射到输出画幅，则复刻投影为 `S · H_f · A`，最后除以齐次坐标。一次登记后，用已知参考点检查矩阵方向、裁切和画幅缩放。CSS、OpenCV 或其他引擎按各自矩阵布局写入。
- 同镜换参考帧时，用共同锚点求出「主参考帧 → 当前窗参考帧」的变换，右乘到当前窗逐帧矩阵上。先用重叠帧与独立点验算。缺少共同锚点时保留两个局部坐标，显式标明手工衔接。活动项若在输出画幅中取样，先用 `S` 的逆变换转回分析像素，再用 `H_f` 的逆变换回到参考坐标。用于验收的点留出，不参加测量或注册拟合。
- 对 `validated` 使用实测投影，对 `limited` 先看对象所在区域的覆盖图与独立锚点，接受时保留有限标记。`reference_only` 仅登记该参考帧。`single_frame` 直接按该帧重建。短缺口仅在同镜且参考坐标一致时插值锚点，并检查位移、尺度和速度。长缺口、证据不足或非刚体转场可用手工关键帧或专门图层，逐区间记录回退。切点两边分别处理。
- 边缘宽度是成片亮度从 10% 到 90% 的像素距离。渲染参数要结合字体笔画、投影缩放和已有模糊校准。只有按理想阶跃边响应近似高斯时，才可用 `σ ≈ 宽度 / 2.563` 作初值。对 2D 平面图形，区域排序和 `focus.evidence` 描述清晰度证据；**对 3D / Blender 场景，按[三维场景与 Blender 逆向精测](#三维场景与-blender-逆向精测)中 `scene3d.json` 的 `lookdev_feature_gates` 条件开关实装对焦距离、体积雾、光晕、快门与色散——原片实测为 `true` 时不得以“物理参数无法唯一反解”为由关闭，原片实测为 `false` 时亦不得凭空添加**。

### 对照验收

1. 在参考帧和一个明显不同的机位分别试渲染，从实际输出读取固定点的位置。再抽查段首尾、切点前后、动作首帧与完成帧、拉远或推近最快处、焦点切换和每个回退边界。
2. 对同一个留出的锚点，记下原片观测、测量预测和渲染观测。分别报告「测量预测到原片」和「渲染观测到原片」的像素误差。沿可比边缘复测原片与渲染的过渡宽度。对明显的拖影，比较方向和长度。
3. 合并各窗的可编辑图层和时间线。从项目记录指定的入口重新打开并试渲染，确认依赖可读、各窗引用约定的共享资产版本。检查同镜跨窗的状态、位置、速度和层级，核对最终帧数、切点及 PTS。实际修改一项关键文字、图形、镜头参数或动画关键帧，重渲染受影响的范围并确认修改生效，再用选定版本交付。若是投影页面的换字，至少渲染同一镜头的两个机位检查图层附着。检查复刻工程及成片的画面素材来源。
4. 回填复刻清单，标出每镜实际使用的字段、数据版本或文件、有限观测、回退区间和仍可见的差异。局部误差超出原片观测的不确定度时，回查参考帧登记、坐标和模糊实现。
5. 对做过分层逐帧精测的动效，按[连续动效短窗精测](#连续动效短窗精测)交付同步对照，注明仍有差异的时序或轨迹。
6. 默认将[对齐后的原混音](#声画拆解与试听)作为一条独立、可替换的音轨接入总工程，按源时间偏移对齐所选范围。分轨可供编辑，避免与原混音重复播放。核对声画起始偏移、跨窗连续性和关键声画事件。无原声时记录缺失并完成画面验收，用户指定其他音轨方案时照办。
7. Blender 每段首版、修改后复测和总装代表帧，必须先做**工程级静态审计**，再对照 `lookdev-keyframes.json` 覆盖各光学工况代表帧对原片与实际渲染分别运行 `scene3d` 与双向严格裁判：
   ~~~bash
   # (a) 工程静态审计（防为追求速度暗中降级引擎/关光追/砍弹射/丢体积/单层弱 Glare）：
   python scripts/decompose.py audit-blend /path/to/replica.blend \
     --scene3d /path/to/orig_peak/scene3d.json --scene3d /path/to/orig_closeup/scene3d.json \
     --out /path/to/blend_audit_gate --strict

   # (b) 像素双向闭环验收（按 lookdev-keyframes.json 覆盖全部光学工况）：
   python scripts/decompose.py compare /path/to/orig/scene3d.json /path/to/render/scene3d.json --out /path/to/compare_gate --strict
   ~~~
   - **`audit-blend` 工程静态审计（方案 A 零妥协红线）**：生成 `blend_audit.json` 与 `blend_audit.md`。硬伤直接判 `FAIL`（退出码 `2`）：原片实测含自发光间接溢光、体积雾或复杂反射时降级为 EEVEE；任何非平面 3D 终稿使用 `use_raytracing = False` 的无光追 EEVEE；Cycles 漫反射/镜面/透明/体积弹射低于原片要求；低采样妥协；原片有体积雾或辉光却缺失对应节点，或原片需双层辉光却只挂单个高阈值弱 Glare。同时对高反差场景中的相对超大面积补光、跨明暗工况静态未动画化合成器、非自发光面混高 `Emission` 等主观风险项给出 `WARN` 与具体灯具/节点清单。
   - **`compare` 双向闭环裁判**：生成 `compare_report.json`、`compare_report.md` 与四联差异热力图 `compare_report.png`，强制检查以下 4 组门槛：
     - **19 项证据门控开关一致性 (`lookdev_feature_gates`)**：原片为 `true` 的必须实装（含 `emissive_indirect_spill`），原片为 `false` 的干净/光滑场景必须保持关闭；
     - **全画幅光度、间接溢光、4 象限反差与边缘柔和度双向匹配**：`p50_midtone`（`±45%`）、`p85_key_level`（`±40%`）、`near_bloom_linear_lum`（超 `±50%` 判 `FAIL`）、`far_volumetric_excess`（缺失超 `55%` 判 `FAIL`）、`emissive_spill_chromatic_energy`（自发光周边彩光溢散跌破原片 `55%` 判 `FAIL`）、相对原片的 `non_core_crushed_black_ratio`（非光源区死黑塌陷增量校验，不误伤黑底棚拍）、`regional_tonal_contrast`（4 象限局部反差防平光洗平，同帧 `SSIM` 偏低时优先对位几何）与 `shadow_penumbra_width_px`（`0.55×–1.85×`）；
     - **材质反作弊检查（防洒白点/防拉伸/防亮面偏光）**：核对 `shading_paradigm`、`surface_finish_class`、`roughness_median`（`±0.12`）、**`wear_speckle_area_ratio` 双向范围（`0.50×–1.75×`）**、**亮面独立细纹 `bright_surface_fine_rms`** 以及 **`texture_stretch_anisotropy`**；
     - **视觉结构与轮廓对齐（`SSIM` / `Edge IoU(4px)` / 象限热力图）**：自动定位造型/角色姿势/字体/穿模偏差最大的象限并在 `compare_report.png` 中高亮标出；凡 `VERDICT=FAIL` 须按清单返修后再交付。

   **通用 3D 布光与光传输准则**：(1) 禁止为了渲染速度降级正式验收与交付引擎，远程 GPU 不可用时改走本机全质量渲染或先向用户汇报耗时征求决策；(2) 按原片 `shadow_penumbra_width_px` 与 `key_to_fill_linear_ratio` 配置与主体尺度相称的灯光，禁止在强明暗对比场景中用远超景深尺度的超大泛光灯洗平立体感与表面材质；(3) 连续镜头跨越明暗或辉光开关工况（如室外进室内、强发光宽景切暗部特写）时，必须对合成器辉光/曝光曲线做关键帧过渡或分场景布光；(4) 强反射材质（漆面、清漆、金属、玻璃、湿面）必须在光追或有效反射探头环境下校准底色与粗糙度。

8. 总负责人从总工程入口重开并导出，核对依赖、资产版本、声画同步、运动和真实切点。每个有对照原片的范围都要对实际整合成片运行 `continuity` 并逐项回看候选，局部返修须覆盖两端接缝。整片结论取自本次最终导出；分段通过但接缝异常时，整片按报告保留未通过状态。摘要写明通过、需返修、待复核各有多少段。缺少本段对比证据时保留待复核。另列交付版本、整片结论、可见差异和接缝时间码，再链接单项、分段与整片报告。见[镜头连续性验收](continuity.md)。

## 三维场景与 Blender 逆向精测

### 1. 2D/2.5D 平面动效与 3D Blender 场景的自动判别分流

`decompose.py scene3d` 会自动在 `scene3d.json` 的 `scene_paradigm_classification` 字段输出当前镜头的定量判别结果（同时保留原有 2D/2.5D `measure` 流程 100% 不变）：

| `detected_paradigm` | 定量判据 | 适用管线与目标工程 |
| --- | --- | --- |
| `2D_PLANAR_UI_MOTION` | 灰度直方图前两箱占比 $>0.68$ 且平坦梯度占比 $>0.58$；跨帧特征点单平面 2D 单应性拟合 `holdout_p95_px <= 2.75`、内点率 $\ge 0.80$ | 走原有的 **`decompose.py measure` + 连续动效 + 字体 IoU 精测**，接入 Remotion / AE / CSS / Canvas 等 2D/2.5D 图层工程 |
| `3D_BLENDER_SCENE` | 连续曲面明暗梯度占比 $\ge 0.24$；检出三维平行线消失点汇聚或轴测平行线簇；多深度层光流速度视差比 `P85/P20 > 1.35`（或单平面 `holdout_p95_px > 3.5`）；或存在三维光源/体积散射光晕剖面 | 走 **`decompose.py scene3d` 六维三维逆向精测**，按输出的 `scene3d.json`、分层高度遮罩与光学参数接入 Blender |
| `HYBRID_2D_OVER_3D` | 同时满足 3D 底景判据（`score_3d >= 2.5`）与大面积画幅锁定/平面文字 UI 特征（`score_2d >= 2.0`） | **分层混用**：三维底景、相机与灯光走 `scene3d` 进 Blender；叠加在画幅或独立平面上的 2D 字幕/UI 走 `measure` 与字体精测 |

### 2. `scene3d.json` 六大通用维度与 Blender 参数换算表

即使不传 `--corners`，`decompose.py scene3d` 也会对目标帧及 `--window` 邻帧完成全画幅 3D 诊断并输出 `scene3d.json` 与四联诊断图 `diagnostics_3d.png`；当传入 `--corners "x_tl,y_tl;x_tr,y_tr;x_br,y_br;x_bl,y_bl"` 时，还会对选定的三维平面构件执行透视修正展平、体素/阵列周期检测、分层 3D 置换遮罩提取与扩边干净背景板生成：

| `scene3d.json` 字段路径 | 物理含义与计算方法 | Blender 5.x 接入方法 |
| --- | --- | --- |
| `pillar_1_camera_and_projection.projection_type` | 由平行线簇交角与消失点距离判定 `PERSP` 或 `ORTHO` | `cam_data.type = 'PERSP'` 或 `'ORTHO'` |
| `pillar_1_camera_and_projection.estimated_focal_mm` | 由正交消失点约束 $(VP_i-c)^\top(VP_j-c) = -f_{\text{px}}^2$ 换算的 36mm 全画幅等效焦距 | `cam_data.sensor_width = 36.0`，`cam_data.lens = estimated_focal_mm` |
| `pillar_1_camera_and_projection.planar_object_3d` | 由构件左右投影高度比 $D_L/D_R = h_R/h_L$ 反解的相机空间 3D 顶点 `P_TL, P_TR, P_BR, P_BL`、法线与 `explicit_focus_distance_m` | 用四角 3D 坐标按逆深度 $1/D(u) = (1-u)/D_L + u/D_R$ 直接生成网格顶点；景深显式设置 `cam_data.dof.focus_distance = explicit_focus_distance_m`（严禁绑定位于原点的父级空物体） |
| `pillar_1_camera_and_projection.framing_and_lens_geometry` | 检测宽银幕上下/左右黑边遮罩（`letterbox_detected`、`active_content_aspect_ratio`）与边缘长直线弯曲度（`BARREL_WIDE` / `PINCUSHION_TELE` / `RECTILINEAR_NONE`） | 设置输出画幅裁剪/黑边遮罩与合成器 `Lens Distortion` 桶形/枕形畸变系数 |
| `pillar_2_geometry_and_topology.texture_sampling_mode` | 由展平纹理一阶差分自相关检测像素阶跃周期 `voxel_pixel_step_px` | 体素/像素风设为 `tex_node.interpolation = 'Closest'`，写实风设为 `'Linear'` |

### 4. 高精写实静态场景 3DGS 本地重建与 Blender 5.2 渲染（`gs3d_pipeline.py`）

当场景属于**高精写实有机曲面 / 3A 级密集静态纹理**且用户目标为**视频新视角自由运镜**（已前置同意 `CAP-3D-PHOTOREAL-3DGS` 视角锥与重打光边界）时，可使用 `scripts/gs3d_pipeline.py` 依次完成抽帧、COLMAP 4.2 以上的稀疏重建和 Brush 训练，再将 PLY 导入 Blender。安装与平台验证见[可选 3DGS](../INSTALL.md#可选-3dgs)。

~~~bash
python scripts/gs3d_pipeline.py \
  --video "/path/to/source.mp4" \
  --out-dir "/path/to/project_3dgs" \
  --start 23.5 --end 30.1 --fps 18 --max-side 1600 \
  --crop-bottom 0.068 --steps 20000 --max-splats 500000 --stage all
~~~

关键操作门槛与避坑规范：
1. **严格预筛刚体静光段**：抽帧前必须切掉液化/鱼眼转场、第一人称手臂/脚步等动态前景以及光照突变段；画面边缘存在画幅锁定水印时用 `--crop-bottom` / `--crop-top` 裁除，防止练出镜头前漂浮灰斑。
2. **用 COLMAP 平移基线预判安全自由运镜角**：`--stage colmap`（或 `--stage baseline`）会自动计算 `lateral_to_depth_ratio` 与 `dolly_to_depth_ratio`：
   - **大范围平移/环拍段（`lateral_to_depth_ratio >= 0.45`）**：支持 `±25°~45°` 较宽自由环绕；
   - **以直推为主的走廊/桥面段（`dolly >= 0.35`、`lateral < 0.16`）**：沿路径平稳推拉、轻度拉升及远中景 `±8°~12°` 弧线画质极佳，但**不可对未绕拍过的近景单体做 `±20°~45°` 环绕**；
   - **纯原地转头段**：仅限 `±3°~8°` 微视差；若用户要对单个写实主体做 `±45°~360°` 特写环绕或重打光，须明确切换至 **Image-to-3D 实体网格路线（`CAP-3D-IMG2MESH`）**。
3. **Apple Silicon / Metal 基准的 Blender 5.2 渲染路径**：
   - 使用 **KIRI 3DGS Render v5.1+** 扩展导入 `.ply`；在 macOS 上导入前先从扩展资源目录预追加 `KIRI_3DGS_Render_Material` 以规避 Windows 反斜杠路径问题；
   - **最终出片严禁使用 EEVEE 几何节点预览（`KIRI_3DGS_Render_GN`）**（慢且发虚拉丝）；必须调用 `gpu.init()` + `sna.dgs_render_create_proxy_from_mesh_eafbb()` + `sna.dgs_render_advanced_render_147af()` 走原生 Metal GPU 光栅化（`~0.30 s/帧`），新视角渲染优先设 `r2_sh_degree = 0` 避免高阶球谐外推偏色；
   - 构图尽量避开紧贴脚底的高反射镜面水池（镜面虚像违背静态三角化假设）。

## 声画拆解与试听

### 运行与缓存

先运行 `decompose.py scan`，把生成的 `source.json` 交给音频脚本。Python 环境、分轨权重及缓存配置见[可选音频](../INSTALL.md#可选音频)。

~~~bash
python scripts/soundtrack.py prepare "项目/原片.mp4" "项目/音频" --scan "项目/扫查/source.json" --checkpoint "模型/checkpoint-multi.ckpt"
~~~

Bandit 默认自动选 Apple GPU 或 CPU，自动模式遇到 GPU 推理错误时用 CPU 重试。Beat This! 使用 CPU。两者推理均在本地。

`prepare` 默认沿用扫查起止帧。可用 `--start`、`--end` 覆写为左闭右开的源帧范围。 `soundtrack.json` 登记原片标识、首帧源 PTS、音轨首时刻、切片起止及样本原点、可用轨道、找拍状态和回退原因。窗口 WAV 的第 0 个样本对应其中的 `sample_origin_s`，所有表格中的秒数均以原片首帧为零。原混音保持原采样率、声道和电平。Bandit 内部使用 48 kHz 双声道，在 8 秒窗口间做 2 秒交叉淡化，输出按原采样率和同长度回写。原素材缺少音轨时登记 `no_audio`，分轨失败则继续用原混音查候选。时间戳缺测时在清单注明。

- `--reuse /path/to/previous/soundtrack.json` 核对同一源文件、原点、采样率和范围覆盖，从既有分轨取样。无可靠重叠的旧轨需要重新对齐或重跑。
- `--tracks /path/to/tracks.json` 传已复核的独立轨。每项写出文件、文件第一个音频样本在源时间轴的秒数，以及对齐证据。相对文件路径以 JSON 所在目录为基准。轨名为 `speech`、`music`、`effects`，未提供的轨道仍用分离流程补。单独用于分析的原版 BGM 写入 `music_reference`，便于保留成片 BGM 的剪切、入点和音量变化。一个偏移适用于匀速连续段，有跳剪、循环或变速时，先逐段对齐并整理为连续参考轨，否则留用成片分轨。

~~~json
{
  "music_reference": {
    "path": "bgm-aligned.wav",
    "start_s": 1.25,
    "evidence": "和原混音核对开头与段尾两个鼓点，偏移一致"
  }
}
~~~

### 审核与输出

`transients.csv` 给出原混音和可用音效轨的频带变化峰，窗口约 23 ms、步长约 5 ms。表中标的是峰值候选。要测起音和尾部，检查对应轨及原混音的局部波形和频谱。`beats.csv` 给拍点与小节首拍候选。`music-level.csv` 用约 250 ms 的窗口记录音乐电平，帮助找入场、渐强、降音和停顿。默认用这些本地数据交叉核对，尤其检查低电平、口播串入、半拍与倍速歧义，以及音乐中途换曲或断开的位置。需要听辨而当前无法直接听辨的项目在审核记录中标为「待听辨」，附可供复核的试听文件。

对快剪卡点片、MV 或视觉重击密集的镜头，可运行 `soundtrack.py beat-lock` 自动将音频瞬态/拍点与视频帧的硬切（`HARD_CUT`）、亮度闪白跳变（`FLASH_JUMP`）及运动冲击峰（`MOTION_IMPULSE`）在容差窗口（默认 `±85 ms`）内配对，直接导出 `av_beat_lock.json` 与 `av_beat_lock.csv`：

~~~bash
python scripts/soundtrack.py beat-lock /path/to/source.mp4 /path/to/beat-lock \
  --start 0 --end 150 --tolerance-ms 85
# 若已运行 prepare，可传 --scan /path/to/source.json --soundtrack /path/to/audio/soundtrack.json 复用已有分轨与拍点
~~~

顺着每段画面逐个确认音效、音乐事件和画面配合。局部动作可用起动、接触、显露、峰值或结束帧，长声可按区间说明它跨了哪些镜头。每条对应保留支持证据与可见限制。只找到音效或只找到动作的条目可留空另一侧。短点过弱、不同轨同时存在或可能只是音乐时，降低置信度并说明疑点。

把审核后的结果保存为 `review.json`。每项使用一个源帧和一项采用的声音时间。同一画面在音乐轨和音效轨均有事件时写两行。 `anchor` 选择 `onset`、`peak`、`end`、`beat` 或 `boundary`。可记录区间，两端分别填入 `onset_s` 和 `end_s`。置信度用 `high`、`medium`、`low`、`unmatched`。具体字段如下示例：

~~~json
{
  "events": [
    {
      "frame": 5, "action": "开始键入拼音", "phase": "起动",
      "layer": "effects", "audio_event": "成组键击",
      "onset_s": 0.144, "peak_s": 0.148, "end_s": 0.883,
      "anchor": "onset", "relation": "键击略先响，随后贴着输入动作延续",
      "confidence": "high", "evidence": "原混音和音效轨可辨连续短击，覆盖拼音输入"
    }
  ],
  "listen": [[0.05, 1.05]]
}
~~~

~~~bash
python scripts/soundtrack.py match /path/to/review-output \
  --scan /path/to/scan/source.json --soundtrack /path/to/audio/soundtrack.json \
  --review /path/to/review.json
~~~

`av-events.csv` 按 `音频时刻 − 画面相对时间` 计算毫秒偏差，负数表示声音先到。源 PTS 和帧间距同时保留，可变帧率按实际间隔核对。`listen` 每项为源时钟下的起止秒，导出同样本范围的原混音和可用分轨，使用 `window.json` 对回画面。交付正文按实际证据挑出有代表性的音效、节拍和段落变化，写清它们与画面是提前铺垫、同步强调还是跨镜延续。
